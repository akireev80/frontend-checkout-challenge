# Фронтенд каталога и чекаута (Next.js 15)

Интерфейс для интернет-магазина, разработанный в рамках тестового задания. Интегрирован с асинхронным API бэкенда Fastify через общий пакет контрактов `@checkout/contracts`.

## 🚀 Что сделано и как устроено

- **Разделение компонентов:** Страницы (`page.tsx`) сделаны серверными (Server Components) для первичной загрузки каталога. Вся интерактивная логика, формы и корзина вынесены в клиентские компоненты из папки `components/`.
- **Управление состоянием:** Сессия, корзина и процесс оплаты вынесены в Zustand. Стор синхронизируется с `localStorage` для сохранения состояния гостя между перезагрузками.
- **Решение конфликтов версий (409):** При любом изменении состава корзины во время чекаута квота доставки (`quote`) автоматически сбрасывается в `null`. Это защищает бэкенд от конфликтов версий (`CART_VERSION_CONFLICT`), если пользователь вернулся назад в каталог и изменил состав заказа.
- **Асинхронная оплата (Polling):** Метод оплаты запускает фоновый опрос статуса заказа через `setInterval` (раз в секунду). При получении финального статуса от банка (`paid` или `confirmed`), таймер очищается, и происходит SPA-переход на страницу успеха. Логика опроса восстанавливается при перезагрузке страницы.
- **UX и валидация:** Ошибки валидации от API (формат телефона, некорректный адрес курьера) перехватываются и переводятся на понятный русский язык прямо под инпутами. Формы семантичны и полностью доступны для навигации с клавиатуры (`Tab` / `Enter`).
- **Оптимизация:** Картинки товаров переведены в `.webp` и добавлены в `public/`. Для импортов настроен алиас `@/*` в `tsconfig.json`.

## 🛠️ Команды запуска из корня репозитория

- `npm run dev:web` — запуск фронтенда в dev-режиме (`localhost:3000`)
- `npm run build:web` — продакшен-сборка и проверка типов TypeScript
- `npm run start:web` — запуск собранного продакшен-билда фронтенда
